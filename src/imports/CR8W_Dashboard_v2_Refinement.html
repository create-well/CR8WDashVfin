CR8W Dashboard v2 — Refinement & Usage Specification

The dashboard is the riverbank. It holds the current so the team doesn’t have to think about where to go.
CREATE WELL COLLECTIVE · LAS VEGAS · 2026

Current State Assessment

The v1 dashboard (Figma + live at cr8w.overtinkr.com) has strong visual bones and the right metaphorical language. What’s missing is functional depth — the dashboard is a beautiful shell with no live data, no clear ownership, and no connection to the team’s actual operating rhythm.

What Works

  • The mood check-in (flowing / foggy / fired up) — a somatic entry point
  • The greeting by name — personal, warm
  • The stats card grid (Moves, Stations, Guests, Team) — the right nouns for a retreat/workshop collective
  • The brand palette (Deep Rust, Sandstone, Peach Haze, Clay Velour, Camel Sun) — consistent across the whole experience, now mapped to the official 2025 brand board hexes
  • The tab architecture (THE WELL, WORKSHOPS, GEYSER, PLAYGROUND, CO-FLOW) — the metaphors are correct

What Needs Tending

  • All stats read 0 — no data plumbing
  • Calendar shows a cookie-consent wall, not events
  • Tools are static icons, not connected links
  • MBody is a “SPIN” button with no backend
  • “Notes from the well” is two cards, not a knowledge base
  • No role visibility — who’s Flow Keeper this week? Who’s holding what?
  • No weekly rhythm view — the Monday→Wednesday→Thursday→Friday flow is invisible
  • No question bank access
  • No Flowtainer links
  • The dashboard doesn’t know about the podcast, the retreat, or the workshop pipeline

v2 Design Principles

  1. Flow over force. Every element earns its place. If it doesn’t serve a weekly decision, it goes.
  2. The banks hold the water. The dashboard should make the operating rhythm visible — not just possible.
  3. Three users, one view. Monny, Sunshine, and Bingle each see what they need without switching contexts.
  4. Live data or nothing. A stat that reads 0 is worse than no stat. Connect it or hide it.
  5. Metaphor is functional. “The Well” isn’t just a name. It’s where drops become knowledge.

Technical Notes

Preferred Stack (Lightweight)

  • Frontend: The existing React/Next.js setup (or simple HTML/CSS/JS if rebuilding)
  • Data Layer: Google Sheets API (for lightweight, team-editable data) or Airtable
  • Calendar: Google Calendar API (server-side fetch, no client auth)
  • Auth: Simple password gate (“monnytinks”) or shared login
  • Hosting: Vercel (existing) or Netlify

Why Google Sheets as the Database

  • The whole team can edit it without learning a new tool
  • It’s the source of truth for guest lists, station readiness, task status
  • The dashboard reads from it; the team writes to it
  • No custom CMS required

Design Refinements (Visual)

  1. Card Hover States: Subtle Deep Rust shadow on hover, not a color shift. The cards feel tactile.
  2. Empty States: When a stat is 0, show “—” instead of “0.” Zero reads as failure. “—” reads as “not yet.”
  3. Loading States: Skeleton screens in Sandstone/Deep Rust gradient, not spinners. The well is filling.
  4. Error States: “The water is murky. Try again.” Not “Error 404.” The metaphor holds even in failure.
  5. Mobile: The card grid becomes a single column. The weekly rhythm strip becomes a swipeable carousel.
  6. Dark Mode: Deep Black (#101010) background, Sandstone text, Deep Rust accents. The well at night.

Flowing > forcing. The dashboard is the riverbank. Build the banks so the water can move.
